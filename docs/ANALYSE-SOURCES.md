**Atelier de référence :** Séance 10 — lundi 26 octobre 2026 · Module 03 · Semaine 05

## Sources consultées

1. Archive utilisateur `supports-seance-10.zip` (28 entrées). Copie inchangée dans `sources-originales/`.
2. Document principal `support-seance-10-fiche-projet-v1.md` : le support porte une date de préparation **03 juillet 2026**. Il définit la finalité S10, les objectifs, 12 rubriques, les prompts et la pratique.

4. Résultats exemples dans `prompts-exécutés-seance-10/` : démonstrations conservées dans `ressources-selectionnees/` pour étude, non considérées comme validations du module d'Automne.
5. Dépôts GitHub S07, S08, S09 : progression Automne et architecture Vite / formation interactive.

## Adaptations explicites

- **Calendrier** : S10 lundi **26 octobre 2026**, semaine pédagogique **05**. Le support de juillet 2026 demeure une source historique, non le calendrier actuel.
- **Chemin** : plusieurs prompts originaux écrivent `02-DOCUMENTS/fiche-projet-v1.md`, alors que S09 organise `03-documents/note-cadrage-courte.md`. Chemin canonique adapté : `03-documents/fiche-projet-v1.md`. Les copies Markdown de `ressources-selectionnees/` sont désormais explicitement adaptées au cycle `challenge-100jours-automne-2026` ; seul le ZIP dans `sources-originales/` fait foi comme original inchangé.
- **Déroulé** : pratique S09 → S10 → S11. Les 22 slides et le formulaire sont une synthèse originale, non une reproduction à l'identique des fichiers historiques.
- **Démonstrations** : « rôle de l'humain dans la production IA » reprend le sujet des résultats de l'archive. Les trois autres cas (scolaire, entrepreneuriat, management) sont fictifs et créés pour diversifier l'enseignement.
- **Fonctions** : l'application construit et exporte un Markdown à partir des saisies utilisateur ; elle ne fait pas de génération par IA, ne contacte pas GitHub et ne certifie pas la validité d'un contenu.
- **Workflow de publication** : prévu dans le dépôt local, activation et push non réalisés automatiquement.

## Points à contrôler humainement

- Cohérence de la séance avec les consignes éditoriales du Challenge.
- Exactitude et exhaustivité des rubriques en situation réelle.
- Relecture des exemples par le formateur.
- Validation des fichiers sources et accord de publication des visuels.
- Choix de conserver les exemples fictifs si la publication est publique.
